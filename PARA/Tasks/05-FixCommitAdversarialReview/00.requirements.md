# Requirements — 05-FixCommitAdversarialReview

Deliverable: `01-adversarial-review.md` in this folder — per-vector PASS/FAIL with
template-level evidence. Plus a fix commit **only if** a real defect is found.

## Acceptance criteria

- Every one of the 7 attack vectors gets an explicit PASS/FAIL verdict backed by
  quoted template evidence (resource type, property, logical ID), not by reading
  the TypeScript and asserting.
- Judged **only** against the commit's own claims and REVIEW.md's top-3 spec. A
  true claim that is merely incomplete is not a defect.
- No new hardening proposed in code. Out-of-scope ideas go to `00.rejected-ideas.md`.
- Real defect found → one commit fixing it, same message discipline (what/why,
  out of scope, live rollout risk + mitigation), synth clean, pushed.
- Nothing found → say so plainly. "No change needed" is a valid, good result.
- Nothing deployed; no AWS account used.

## Constraints

- Budget ~40 minutes, hard stop.
