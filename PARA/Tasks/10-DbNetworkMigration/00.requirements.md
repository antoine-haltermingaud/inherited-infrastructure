# Requirements — 10-DbNetworkMigration

**Planned for Delta week 2–3 as a scheduled maintenance window. Deliberately NOT implemented in the take-home** — REVIEW.md explicitly defers it out of week one; it is a downtime migration.

## Acceptance criteria

- RDS in PRIVATE_WITH_EGRESS subnets, `publiclyAccessible: false`, `storageEncrypted: true` (KMS), all in one announced window.
- Runbook written and reviewed BEFORE the window: freeze writes → final snapshot → encrypted restore → verify row counts/checksums → cutover endpoint via CDK → unfreeze → old instance kept stopped for 7 days as rollback.
- Post-migration: team access path (task 07) still works; backups (7d) and deletion protection verified re-applied on the new instance.
- Rollback tested in reasoning: at which step is rollback no longer "point back at old instance"? Marked explicitly in the runbook.

## Constraints

- Window sized honestly (snapshot+restore time scales with 100 GB); communicated to app teams; not scheduled until tasks 06–09 are done and quiet.
