# Context — 10-DbNetworkMigration

- Current state: RDS sits in PUBLIC subnets with `publiclyAccessible: true` (`lib/data-stack.ts:45-46`) and `storageEncrypted: false` (:54). Exposure is already mitigated by SG rules (`655147d`), so this is the *end-state* fix, not an emergency.
- Why it waits: `REVIEW.md` "deliberately waiting" — re-homing a live single-AZ DB is the one genuinely risky migration in this repo, and storage encryption CANNOT be enabled in place (snapshot → encrypted copy → restore → cutover, new endpoint).
- Why combined: both need a downtime window; production takes ONE window instead of two.
- Endpoint wiring: app gets DB_HOST from the CFN attribute, so the CDK-level cutover rewires it — but a restored instance is a NEW instance; data written between snapshot and cutover must be handled (brief write freeze or dump/restore delta).
