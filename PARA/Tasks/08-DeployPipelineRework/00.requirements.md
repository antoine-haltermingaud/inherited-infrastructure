# Requirements — 08-DeployPipelineRework

**Planned for Delta week one (Thursday). Deliberately NOT implemented in the take-home** — REVIEW.md commits to pairing on pipeline rework with the team, not prescribing it.

## Acceptance criteria

- Images tagged with the git SHA; task definition references that SHA (CDK context/parameter wired from the workflow). `latest` may still be pushed as a convenience alias but nothing deploys from it.
- Rollback procedure documented and tested once: redeploy the previous SHA.
- The force-new-deployment / ARN-guessing step is deleted.
- `concurrency:` group serializes deploys; a superseded run cancels or queues.
- Gate before deploy: `npm ci`, `tsc`, `cdk synth`, `app/test.js` — red gate = no deploy.
- Dockerfile: `npm ci --omit=dev` with lockfile, non-root user, HEALTHCHECK.
- First SHA-based deploy verified as a normal rolling deploy (task-def revision change only in the template diff).

## Constraints

- Workflow changes must be reviewable in one PR; no deploy-tooling products (this team runs on GitHub Actions).
