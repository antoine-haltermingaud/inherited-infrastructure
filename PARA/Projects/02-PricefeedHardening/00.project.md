# 02-PricefeedHardening

**State:** next (created 2026-08-24). Activates if/when this plan is actually executed
against a live pricefeed — i.e. a real week one at Delta. `01-PricefeedAssessment`
remains the active project until the take-home is submitted.

## What

`REVIEW.md`'s week-one plan and remaining findings, operationalized: every outstanding
fix is a ticketed, sequenced task with its own context, acceptance criteria, migration
risk, and rejected alternatives.

## Why

A plan in prose is a promise; a plan in tickets is a backlog. This project turns
"here's what I'd do next" into "here's next, already sequenced" — and makes the
deliberate *deferrals* (Multi-AZ as a priced decision, the subnet move as a scheduled
window) first-class tracked items rather than footnotes.

**Nothing in this project is implemented in the take-home. By design** — README Part 2
caps the fix commit at the top 2–3 findings, and several of these tasks require access
this exercise doesn't have (CloudTrail evidence, a domain decision, a maintenance
window with the team).

trustworthy, no long-lived CI credentials, DB privately homed and encrypted, TLS on,

## Sequencing

Wednesday → 06, 07 · Thursday → 08 · Friday → 09 · week 2–3 window → 10 ·
this month → 11, 12 · whenever convenient → 13. Autoscaling is deliberately absent:
per REVIEW.md it waits for real utilization metrics, and a task without an actionable
trigger is noise.
